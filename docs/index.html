NethermindEth / bflat-riscv64

NativeAOT C# for RISC-V zkVMs

Nethermind's fork of bflat. It compiles C# into a static RISC-V ELF that runs in a zkVM: ZisK, SP1, OpenVM or ZKsync Airbender. Nethermind builds the guest of its stateless executor with it.

Quick start

The image has bflat, the .NET 11 SDK and lld. Mount the current directory and build:

# A ZisK-shaped guest that runs under QEMU or on RISC-V64 Linux
$ docker run --rm --platform linux/amd64 -v "$PWD:/w" -w /w nethermindeth/bflat-riscv64-11 \
    bflat build hello.cs --arch riscv64 --os linux --libc zisk_sim --no-pie --no-pthread \
    --extlib https://github.com/NethermindEth/bflat-libziskos:v1.4.0-alpha.153
$ qemu-riscv64 ./hello
# A guest for the ZisK emulator and prover
$ docker run --rm --platform linux/amd64 -v "$PWD:/w" -w /w nethermindeth/bflat-riscv64-11 \
    bflat build hello.cs --arch riscv64 --os linux --libc zisk --no-pie --no-pthread \
    --extlib https://github.com/NethermindEth/bflat-libziskos:v1.4.0-alpha.153
$ ziskemu -e ./hello

bflat downloads the package from its GitHub release and checks its signature. Build & use has SP1, OpenVM, Airbender and all options.

What a zkVM does not give a guest

A zkVM gives a guest much less than a Linux host. bflat links a small module for each gap. The modules are the same on all five platforms.

  • No kernel: no syscalls, files or processes noos, pal
  • One hart: nothing wakes a blocked call nothread, tls, guest_subst
  • No loader to start the runtime ubootstrap, eh
  • No floating-point hardware soft-float ABI; nofp for the transcendentals
  • No randomness, no clock; each run must reproduce rng_stupid, gs_cookie
  • Short runs with a known working set ugc-zero, rhp, rhp_native

How a build works

{% include pipeline-diagram.html %}
  1. ILC compiles IL to a RISC-V object. Roslyn compiles C# to IL first. ILC applies the ILC-stage substitutions and the RyuJIT options of the platform.
  2. lld links the object statically. The link adds the runtime, musl and the link-time modules, which use --wrap to replace the OS calls, the thread primitives and some runtime helpers.
  3. The post-link tools change the ELF for the loader. patch_elf.py runs on ZisK, SP1 and Airbender, and flat_image on Airbender.
  4. The entry object starts the runtime. It calls Main. No kernel runs under the guest.

Architecture has the details of each stage.

The runtime

bflat does not use Microsoft's runtime packages. dotnet-riscv builds .NET 11 with its own patch series: 22 patches for the riscv64 base ISA, soft-float and the lp64 ABI, and 67 patches that change RyuJIT, ILC and the NativeAOT runtime for zkVM guests. The riscv32 target adds 7 patches more. Each runtime release is signed, and bflat checks the signature when it downloads the release.

Checks

  1. Contracts and proofs. Each function of the C modules has an ACSL contract. Frama-C proves the eh module, and CBMC proves the bounds of the allocator.
  2. Tests on the guest ISA. The module unit tests run under qemu. The vfprintf parser and the allocator are fuzzed.
  3. Guests in CI. CI builds both images, links a guest for each riscv64 platform and runs the Airbender guests in the Airbender simulator.
  4. bflat-ts on each pull request. The bflat-ts suite runs on zk-testing with the image of the pull request.

Verification lists each check and each CI job.
